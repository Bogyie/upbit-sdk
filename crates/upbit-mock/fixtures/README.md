# Upbit Mock Fixtures

Fixtures are generated by `upbit-mock` from `spec/upbit-rest-api.yaml` at
runtime. The checked-in catalog records the supported fixture classes and the
error envelope so SDK tests can depend on stable mock behavior without freezing
live Upbit market, fee, network, or wallet-state data as SDK constants.

The conformance baseline verifies every REST endpoint has a route and a
representative fixture containing all `response_fields` listed in the spec.
`list_subscriptions` is intentionally excluded from HTTP route coverage because
the spec marks it as `protocol: websocket`.
